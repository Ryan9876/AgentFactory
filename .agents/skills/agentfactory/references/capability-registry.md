# Capability registry V2

`config/capability-registry.yaml` is the canonical multidimensional evidence record and capability-specific execution-host routing source. `capability-routes.csv` maps stable requirement-scoped intents to owners and unavailable behavior. The registry distinguishes Microsoft documentation/support, preview status, organization policy, licensing, Codex host discovery, authentication, tenant execution, cloud synchronization, runtime qualification, user-presence/admin boundaries, known blockers, host routing, and browser roles. `scripts/host_routing.py` selects only among declared hosts for a registered capability.

Evidence is time- and host-specific. Preserve source and date. A documentation hit or CLI help output cannot mark authentication, tenant execution, synchronization, or runtime qualification as passed. Historical Work Radar and V1 evidence remain historical; they do not prove current Codex Cloud readiness.

Unknown capability intent has no automatic fallback: block only dependent tasks with the missing intent and evidence needed. Use the preferred host first. A host fallback is permitted only when that host or its capability surface is unavailable and the alternate host explicitly supports the capability. Never switch hosts around authentication, MFA, consent, permissions, tenant/admin/security policy, licensing, billing, or Production/publication approval. Record tenant and policy constraints as `BLOCKED_BY_TENANT_OR_POLICY` (or the existing equivalent), not as a tool-host error. A `USER_PRESENCE_REQUIRED` or `ADMIN_REQUIRED` boundary stops automation. Keep `BLOCKED`, `FAILED`, `NOT_TESTED`, `CLOUD_SYNCHRONIZED`, and `RUNTIME_QUALIFIED` distinct.

Cloud is the preferred reproducible source engineering and public research host. Desktop Local is preferred for Microsoft tenant-authenticated work and target-runtime qualification. The visible Chrome Stable profile `AgentFactory` supports interactive identity and real-session verification; profile-name mapping is read from local Chrome metadata and its directory identifier is not a portable constant. It is not an unattended-authentication guarantee or a regression profile. Deterministic UI regression uses Chrome for Testing with a disposable isolated profile.

Authenticate PAC before starting or restarting PAC MCP. For each fresh Copilot Studio MCP process, connect through its supported sign-in, verify the organizational account and Development environment, then refresh the live tool catalog. Installation, schema discovery, or prior browser state does not qualify runtime behavior.

Never route GitHub Copilot harness under current constraints. Keep host-composed Work IQ independent from conditional direct Work IQ MCP. Do not make direct Work IQ MCP a default dependency.
